# Portable assessment-course import

This workflow creates a new, source-owned, classless **ASSESSMENT** course using the existing QuantaEdge hierarchy:

    course → versioned test packs → assessments → ordered question snapshots

It extends existing course authoring and portable-assessment package endpoints. It does not add a second runtime, a new API namespace, or database migrations.

## Identifier rules

Three identifiers have different purposes and must not be confused:

- **Stable course key** — generated automatically from the normalized course name plus a deterministic digest suffix. It is not requested from Admin staff. The database enforces uniqueness within the source institution, and same-name assessment courses are rejected with guidance to open the existing course.
- **Public course ID** — generated by PostgreSQL through the registered **INS** prefix. The public format is exactly eight characters: **INS** plus five uppercase alphanumeric characters. Admin staff do not type it; the UI displays the generated value after creation. **INSABCDE** is illustrative only.
- **Internal numeric course ID** — generated by the database and used for foreign keys. It is not requested from Admin staff.

A package also has its own lowercase **package_id** and **package_version**. These are package metadata, not course IDs; the importer validates them and checks for duplicates within the selected course.

## Command-line workflow

The PowerShell runner works with a manifest or a list of portable assessment package files. By default it performs a dry run and no database writes.

    # Run the offline preflight and dry-run with an existing manifest.
    .\scripts\import_assessment_course_local.ps1 -ManifestPath "data\assessment-courses\course.json"

    # Or provide portable package files directly; missing course details are requested interactively.
    .\scripts\import_assessment_course_local.ps1 -PackagePath "data\assessment-courses\tre-1.json","data\assessment-courses\tre-2.json"

    # Explicit apply against localhost PostgreSQL only.
    $env:ASSESSMENT_DATABASE_URL = "postgresql://quantaedge:YOUR_LOCAL_DB_PASSWORD@localhost:5432/quantaedge"
    .\scripts\import_assessment_course_local.ps1 -ManifestPath "data\assessment-courses\course.json" -Apply
    Remove-Item Env:ASSESSMENT_DATABASE_URL

The Python importer refuses non-loopback database hosts and asks for IMPORT before writing unless -Yes is explicitly supplied to the PowerShell runner. A dry run does not need database credentials or the PostgreSQL driver.

## Manifest example

Use schemas/assessment-course-manifest.schema.json for the machine-readable manifest definition. The course fields may be omitted when using an interactive terminal; the importer will ask for them and show examples.

    {
      "schema": "quantaedge.assessment-course-manifest.v1",
      "course": {
          "display_name": "BPSC TRE Computer Science — Previous-Year Practice Series",
        "curriculum_version": "BPSC-TRE-CS-PYQ-SERIES",
        "stream_code": "ASSESSMENT"
      },
      "packages": [
        "packages/tre-1.json",
        "packages/tre-2.json",
        "packages/tre-3.json"
      ]
    }

Paths inside the manifest are relative to the manifest file. Each package must follow quantaedge.portable-assessment-package.v1 and include source metadata, timing/scoring settings, sections, and the real question content.

When metadata is absent, the CLI asks for stable IDs, names, version, issuer, source URL, test settings and other metadata with examples. It never invents a missing question, option, answer or explanation. If a file has no complete sections and questions arrays, provide a completed package file before import.

## Admin Web workflow

Education Admin staff can use **Content Studio → Assessment course importer**:

1. Enter the stable course key, display name, and version. The database generates and displays the public course ID.
2. Select one or more portable assessment JSON files. Fields for the package name, stable package ID/version, source, rights decision, duration, marks and penalty settings are editable so missing metadata can be supplied without editing JSON manually.
3. Validate all packages against the authenticated course and the server-side package validator. Import remains disabled until every package validates.
4. Import the packages. Each import uses the existing authenticated package endpoint, transaction, course binding and pack idempotency rules. If a multi-package run is interrupted, completed packages remain drafts and identical re-imports are safe to retry.
5. Review questions and answers, publish tests through the normal Admin workflow, submit the course release, and complete HRMS review and Marketplace launch as separate steps.

The API obtains the institution from the authenticated HRMS-bound workspace. A JSON package cannot select its tenant or course.

## Lifecycle and safety

- The source tenant remains **QUANTA-EDGE**; no institution-switching field is offered.
- The generic importer uses **assessment_only_course_ready(course_id)**. It does not apply the TRE-specific **tre4_source_package_ready** gate to unrelated assessment courses.
- Each package import creates a DRAFT assessment and DRAFT test pack with ordered question snapshots. Question/answer review status remains pending.
- One CLI apply is transactional for the course graph and all packages. The browser uses the existing transaction per package after validating the full selected set; if interrupted, the course and completed package imports remain unpublished drafts.
- Re-importing the same course identity and package ID/version/content is idempotent. Different content under an existing package version is a conflict; increment the version for revised content.
- Any existing non-DRAFT release, frozen course graph, published Marketplace offer history, inactive identity or ownership/type mismatch blocks import. The importer does not retrofit orphan graphs.
- There are no database schema or migration changes in this implementation. Course authoring service behavior is extended and the existing authenticated package routes are reused; no new runtime API endpoint is introduced by the Admin wizard.
- Import does not approve answers, publish assessments/packs, approve the course release, grant learner access, or publish a Marketplace offer.
