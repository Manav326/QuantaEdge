## 2. Confirmed source fix and guardrail

**Finding `UX-ADMIN-LAYOUT-001` — fixed in source, runtime verification pending.**

The institution-identity branch of `AdminNotificationsPageClient` nested a `div.admin-shell` inside the already-shared `AdminWorkspaceLayout`. The legacy layout reset in `apps/admin/app/globals.css` applies to direct child `main.admin-shell` routes, not this nested `div`; the div therefore retained the legacy two-column grid even though it had no local sidebar. The wrapper now renders a plain `div` containing `main.admin-main`, leaving the shared shell and notification business logic unchanged.

A new CI source-contract check, `scripts/check_admin_nested_shell_contract.mjs`, asserts the shared shell owns the persistent sidebar, documents the null behavior of non-persistent nested sidebars, verifies legacy `main.admin-shell` compatibility CSS, and prevents reintroducing the institution notification grid.

This is a structural source correction backed by a regression check. It is **not** yet a browser-rendering pass; validate both identity branches after CI.

## 3. False-positive/risk reviewed and not patched

Legacy Admin pages still contain `AdminSidebar` and `admin-shell` in their source. By themselves, these are not proof of duplicate visible navigation:
- `AdminSidebar` returns `null` inside the shared workspace when its `persistent` prop is not set.
- `apps/admin/app/globals.css` normalizes direct child `main.admin-shell` to a single full-width content column and hides its nested sidebar.
- The structured-lesson preview still has a `persistent` prop in source, but the same direct-child compatibility CSS hides the nested sidebar element.

Do not remove or rework these legacy wrappers wholesale. Verify actual desktop/tablet/mobile rendering and then migrate/rewrite only a confirmed route-specific exception.
