# Reusable textbook content-generation prompt

Copy this prompt into a new chat after the selected class's extraction and visual-candidate workflows have succeeded.

---

**Task:** Prepare source-bound, bilingual Science and Mathematics lesson data for QuantaEdge for Class **{7 or 8}**, using only the verified source artifacts already in this repository.

1. **Resume from the repository, not chat memory.** Read `docs/ai/textbook-extraction-execution.md`, this prompt, `data/structured-lessons/class-6/science/production-index.v1.json` for the existing schema/pattern, and [Issue #56](https://github.com/Manav326/QuantaEdge/issues/56). Check current `main` and the latest relevant tree/blob pointers before editing.
2. **Use only the selected class and source set.** Select Science and Maths Part 1 + Part 2 for both English and Hindi. Resolve every book ID and PDF SHA-256 from the current GHCR index and mirrored manifests. Do not guess, substitute another class/edition, or proceed when source IDs/parts are missing or ambiguous.
3. **Map the chapter before deciding topic count.** Read the extracted page JSONL and rendered source PDF pages. Identify actual numbered headings/subsections in both languages; create one lesson per coherent numbered teaching section/subsection. Do not force a preset topic count. Record exact source PDF and printed page ranges and stable source references.
4. **Build a coverage ledger before finalizing the lessons.** Track every relevant figure/visual, table, activity, example, sidebar/safety note, keyword, summary, end question and “Learning further” task in both language editions. Mark unresolved page boundaries, low-text pages, OCR needs and missing visuals explicitly; do not claim complete coverage until reconciliation is done.
5. **Generate paired lesson JSONs.** Use the current schema and registry. Each topic must have separate Explain and Practice sections, paired EN/HI objectives and explanations, localized labels/captions/alt text/activity instructions/feedback/rubrics, stable locale-neutral IDs, and 8 practice questions—one each of multiple choice, multiple select, true/false, matching, fill blank, image observation, short answer and scenario-based. Validate all renderer contract IDs and answer/matching references.
6. **Keep the content chapter-specific.** Do not teach other chapters' concepts in depth, copy NCERT prose or end questions verbatim, or describe this as Navodaya entrance-exam preparation. AI-written questions and explanations are supplementary learning aids.
7. **Keep visuals safe and reviewable.** Use selected source-bound v3 candidates only for their verified book/hash/page. Do not use a full-page English screenshot as a Hindi visual. Unrendered or unreviewed visuals and all dependent image-observation questions must remain blocked from student rendering. Check rights/provenance, accurate meaning, translated labels, contrast, readability and accessibility.
8. **Validate before checkpointing.** Parse every JSON; validate unique topic/question IDs; non-empty EN/HI content in all learner-visible fields; one item per registered question type; answer/option/matching/rubric references; source-book/hash/page identity; exact chapter/topic scope; coverage-ledger consistency; and publication gates. Report structural checks separately from source completeness and human review.
9. **Stage in one chapter batch.** Add only additive structured data, source-coverage ledger and index/resume documentation. Do not modify runtime UI, APIs, student delivery or existing lesson records unless separately instructed. Do not commit each topic or move branch refs while authoring. Update Issue #56 once after the chapter batch is validated, recording the exact full staged tree SHA, per-file blob SHAs, counts, test results, blockers and the next chapter/action. Commit only when the user explicitly requests it.

**Deliverable:** the chapter's paired EN/HI lesson JSONs, source-coverage ledger, updated production index, concise source/review report, structural validation results, and a resume-safe Issue #56 checkpoint. Treat generated data as draft-only and non-publishable until human source/science/bilingual/visual approval.
